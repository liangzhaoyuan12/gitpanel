# Руководство пользователя Gitpulsar

Gitpulsar — нативный Git-клиент для GNOME, написанный на Rust с использованием GTK4 и libadwaita.

## Установка

### Требования

- GTK 4.12+
- libadwaita 1.4+
- git (для удалённых операций)

#### Fedora

```sh
sudo dnf install gtk4-devel libadwaita-devel
```

#### Ubuntu / Debian

```sh
sudo apt install libgtk-4-dev libadwaita-1-dev
```

#### Arch Linux

```sh
sudo pacman -S gtk4 libadwaita
```

### Сборка и установка

```sh
git clone https://gitlab.com/ilshat.ishdavletov/gitpulsar.git
cd gitpulsar
make install
```

Бинарник, ярлык приложения, иконка и метаданные устанавливаются в `~/.local`. Убедитесь, что `~/.local/bin` в вашем `PATH`.

### Удаление

```sh
make uninstall
```

## Запуск

```sh
gitpulsar-gtk                        # открыть приложение
gitpulsar-gtk /путь/к/проектам       # открыть папку с репозиториями
gitpulsar-gtk /путь/к/репозиторию    # открыть конкретный репозиторий
```

Или через **Ctrl+O** в самом приложении.

## Интерфейс

Приложение состоит из трёх основных панелей:

```
┌─────────────┬──────────────────────────┬──────────────────┐
│  Sidebar    │  Центральная область     │  Правая панель   │
│             │                          │                  │
│  Список     │  Коммиты / Изменения     │  Ветки           │
│  репозит.   │  (переключение Ctrl+1/2) │  Теги            │
│             │                          │  Стэши           │
└─────────────┴──────────────────────────┴──────────────────┘
```

- **Sidebar** (левая) — список репозиториев в рабочей папке. Жёлтая точка — есть незакоммиченные изменения, зелёная стрелка — есть непушнутые коммиты.
- **Центральная область** — переключается между вкладками «Коммиты» и «Изменения».
- **Правая панель** — ветки (локальные и удалённые), теги, стэши. Поиск фильтрует все списки.

## Работа с изменениями

### Просмотр изменений

Перейдите на вкладку **Changes** (Ctrl+2). Файлы разделены на два списка:

- **Unstaged Changes** — изменения в рабочей директории, ещё не добавленные в индекс.
- **Staged Changes** — изменения, готовые к коммиту.

Кликните по файлу, чтобы развернуть его дифф с подсветкой синтаксиса. Подсветка автоматически подстраивается под тёмную или светлую тему.

### Staging файлов

Есть несколько способов добавить файл в индекс (stage):

1. **Кнопка +** — наведите на файл в списке Unstaged, нажмите кнопку «+».
2. **Drag-and-drop** — перетащите файл из Unstaged в Staged.
3. **Stage All** (Ctrl+Shift+S) — добавить все файлы.

Для обратной операции (unstage):
1. **Кнопка −** на файле в Staged.
2. Перетаскивание из Staged в Unstaged.
3. **Unstage All** (Ctrl+Shift+U).

### Partial staging (staging по хункам)

Если файл содержит несколько изменённых участков (хунков), вы можете добавить в индекс только часть из них:

1. Разверните дифф файла, кликнув по нему.
2. Если хунков больше одного, над диффом появятся кнопки **Stage Hunk 1**, **Stage Hunk 2** и т.д.
3. Нажмите нужную кнопку — только выбранный хунк будет добавлен в индекс.

Это полезно, когда в одном файле есть и готовые изменения, и незаконченная работа.

### Отмена изменений (discard)

Наведите на файл в Unstaged и нажмите кнопку корзины. Приложение попросит подтверждение — содержимое файла будет восстановлено из индекса.

### Undo / Redo

- **Ctrl+Z** — отмена последней staging-операции (stage, unstage, discard).
- **Ctrl+Shift+Z** — повтор отменённой операции.

Discard тоже можно отменить — приложение сохраняет содержимое файла перед удалением изменений.

### Коммит

1. Введите сообщение коммита в поле вверху вкладки Changes.
2. Нажмите **Commit** или Ctrl+Enter.
3. Для amend-коммита поставьте галочку «Amend».

## Просмотр истории коммитов

Вкладка **Commits** (Ctrl+1) показывает историю коммитов:

- Каждая строка: хэш, сообщение, автор, время, теги.
- Зелёная точка — коммит ещё не запушен.
- Значок замка — коммит подписан (GPG/SSH).

### Раскрытие коммита

Кликните по коммиту, чтобы увидеть:

1. **Сообщение коммита** крупным шрифтом — summary и body.
2. **Список файлов** — с ограничением (по умолчанию 10, настраивается). Если файлов больше, есть кнопка «Show all».
3. **Details** (свёрнуто по умолчанию) — SHA, parent, автор, дата.

Файлы загружаются асинхронно — интерфейс не блокируется даже на больших коммитах.

### Пагинация

При открытии репозитория загружаются первые 50 коммитов. Внизу списка есть кнопка **Load more commits** для подгрузки следующей страницы.

### Поиск

Используйте строку поиска (Ctrl+F) для фильтрации коммитов по тексту сообщения.

## Удалённые операции

| Действие | Горячая клавиша |
|---|---|
| Fetch | Ctrl+Shift+F |
| Pull | Ctrl+Shift+L |
| Push | Ctrl+Shift+P |

Force push доступен через меню (☰ → Force Push).

Удалённые операции выполняются через git CLI (не через git2), что обеспечивает надёжную работу с SSH-ключами и разными конфигурациями.

## Ветки и теги

Правая панель содержит:

- **Local branches** — локальные ветки. Текущая ветка выделена. Кнопка «+» для создания новой.
- **Remote branches** — удалённые ветки. Двойной клик — checkout.
- **Tags** — список тегов.
- **Stashes** — список стэшей с кнопками Apply и Drop.

Поиск вверху панели фильтрует все четыре списка одновременно.

## Stash

| Действие | Горячая клавиша |
|---|---|
| Stash save | Ctrl+Alt+S |
| Stash pop | Ctrl+Alt+P |

Управление стэшами (apply, drop) также доступно через правую панель.

## .gitignore

Меню ☰ → **Edit .gitignore** открывает текстовый редактор с содержимым `.gitignore`. Сохранение автоматически обновляет статус файлов.

## Настройки

Меню ☰ → **Preferences**:

- **Date Format** — европейский (dd.MM.yyyy), ISO (yyyy-MM-dd), американский (MM/dd/yyyy).
- **Auto-refresh interval** — интервал автообновления в секундах (0 = выключено, по умолчанию 15).
- **Commit files limit** — максимальное количество файлов, показываемых в раскрытом коммите (0 = без лимита, по умолчанию 10).
- **Refresh Now** — принудительное обновление.

## Мульти-репозиторий

Откройте папку, содержащую несколько Git-репозиториев. Gitpulsar автоматически найдёт их (сканирование на 1 уровень глубины) и покажет в sidebar с индикаторами:

- Имя репозитория
- Текущая ветка
- Жёлтая точка — есть изменения
- Зелёная стрелка — есть непушнутые коммиты

Сканирование выполняется параллельно (до 8 потоков), что важно при работе с большим количеством репозиториев.
